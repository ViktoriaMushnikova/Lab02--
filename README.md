1. Потому что double хранит числа в двоичной системе, из-за чего обычные десятичные дроби записываются с небольшой погрешностью. В обычных расчётах это неважно, но с деньгами даже копейка расхождения является ошибкой.
2. Случится переполнение, то есть число просто пойдет по кругу от минимального значения. Например, если к максимальному для byte числу 255 прибавить 1, то получится не 256, а 0.
3. В Python тип можно менять на лету и без проблем, а var в C# - это просто неявная типизация. Компилятор сам смотрит на правую часть при компиляции, один раз жестко задает тип, и больше поменять его нельзя. Если var x = 5;, nj x всегда останется int.
4. Всегда возвращает string, даже если мы напечатали цифры.
5. int.Parse сразу сломает программу - вылетает краш с ошибкой. А int.TryParse не падает: программа продолжает работать, просто возвращает false и обнуляет переменную.
6. false значит, что строка была 'кривой' и преобразовать ее в число не получилось. А переменную через out запишется дефолтное значение для чисел - 0.
7. Его всегда стоит использовать, когда данные вводит живой пользователь. Люди часто ошибаются, могут случайно ввести буквы вместо цифр, и если использовать Parse, программа просто вылетит. С TryParse программа не вылетит, и можно будет нормально обработать ошибку.
